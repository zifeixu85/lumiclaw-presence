## Coordinator independent-review correction — 2026-08-04

The Coordinator's independent acceptance review found one blocking AC-04 defect after the initial Executor closeout: `ModelCallSnapshot.pricing` omitted DeepSeek's cache-hit rate, while `estimatedCostUsd` priced every `prompt_tokens` token at the cache-miss rate. The unit fixture incorrectly preserved that overestimate as the expected result. This is an in-scope M2-03 implementation/evidence defect, not an SDD conflict, so no Clarification or M3 expansion is required.

The bounded correction records the official peak cache-hit/cache-miss/output rates for both allowlisted models and calculates each category separately. For the public-safe fixture, flash is `(20 × 0.0028 + 80 × 0.14 + 50 × 0.28) / 1,000,000 = 0.000025256 USD`; pro is `(20 × 0.003625 + 80 × 0.435 + 50 × 0.87) / 1,000,000 = 0.0000783725 USD`. Provider usage now fails closed unless cache-hit and cache-miss fields are either both present with an exact sum equal to `prompt_tokens`, or both absent; the wholly absent case conservatively prices all prompt tokens as cache misses. Provider conformance and the final evidence manifest bind both price tables, both exact cost fixtures, the usage policy and negative mutations for incorrect pricing or contradictory usage.

## Change Request 2 boundary analysis — 2026-08-04

The current Web `public-safe-flight` calls the deterministic domain Flight and only attaches one Mock Producer receipt. Real AgentTeams execution exists in the isolated acceptance runner, while the product `mission-worker` has no runtime supervisor. Therefore adding a direct DeepSeek call to the current endpoint would falsely imply a six-member Live run. Giving the API or worker a Docker socket would instead create a privileged always-on supervisor and exceed SDD-002.

The Coordinator explicitly authorized the bounded middle path: a host-side local UAT runner that binds one exact persisted Mission and the pinned AgentTeams identities, while the API owns a secret-file DeepSeek broker and PostgreSQL remains authoritative. The runner receives only short-lived task-scoped tickets and never the Owner key. Scheme B (surface DeepSeek call plus deterministic Flight) is prohibited; Scheme C (always-on supervisor) is deferred. No unresolved conflict remains, so CR2 is `SPEC_READY` within M2.

## CR2 Fix 1 stdin transport analysis — 2026-08-04

The Coordinator's first real Canary passed secret-file ingress, Compose inspection and exact Live Mission creation, then failed before AgentTeams task execution. Local reproduction against clean Head `c931b77ff723e3d9a098a8a088e8a6e3ffe7cb79` sends four newline-delimited fields to `run-live-deepseek-uat.mjs` and deterministically returns Node status 13: stdout stops after `Organization ID: Live Mission ID:`, while stderr reports an unsettled top-level await at the second `readline.question()`. This confirms a transport defect, not a DeepSeek, AgentTeams, Mission or Secret-mount defect.

The correction is bounded to stdin framing and output handling. One JSON document is read exactly once at each consuming boundary. Node 24.16.0 rejects numeric fd `0` in `node:fs/promises.readFile`, so the implementation uses the numeric-fd-capable `node:fs.readFileSync(0, 'utf8')`; this remains a single non-interactive read and avoids multiple stream consumers. The environment verifier treats the document as secret-bearing memory, forwards it through a captured pipe, validates only a redacted child receipt, and never propagates raw child output. The Runner uses a shared exact-key parser and a top-level redacted error boundary. A conformance-only execution stops immediately after production parsing and returns hashes rather than values, which lets Vitest exercise the real nested child route without Docker, a provider Key or a fake Live claim. Existing exact-project `finally` cleanup remains authoritative and gains evidence assertions. No SDD conflict or M3 expansion exists.
